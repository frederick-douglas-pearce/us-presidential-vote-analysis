Module-specific guidance, moved from the root `CLAUDE.md` (#298). Claude Code loads this file on demand, once a file under this directory is read. The root file's module map and cross-cutting invariants still apply.

## Overview

**The public dashboard (E9, #275)** is the front end of D001's what-if explorer, re-scoped from the analytical mart by [D070](../.claude/specs/decisions.md). It is **live at `https://explore.us-presidential-election-center.org`** and **reads the live public `/v1` API**, bundling no copy of the data — so D030 holds structurally and the API is its own first consumer. Its runtime code references no `run.app` URL and imports nothing from `usvote` (D070(b)). New data shapes are built only when a named chart needs them, as a new snapshot table or `/v1` endpoint, never a Postgres mart object (D070(c)). **The platform is Plotly Dash on App Engine standard** ([D071](../.claude/specs/decisions.md), the verdict of the research spike #276): one pinned F1 instance in a GCP project of its own, `uspv-explore`, whose budget and kill-switch cannot pause the API (#283). Its code lives in this repo under `dashboard/`, outside the `usvote` package — see [`dashboard/`](#dashboard--the-public-dashboard-e9) below. The spec, including every story body and the constraints each one carries, is [`.claude/specs/backlog-dashboard.md`](../.claude/specs/backlog-dashboard.md).

(the structural guards described under
[`dashboard/`](#dashboard--the-public-dashboard-e9)). pytest's `pythonpath` includes
`dashboard`, so they import the `explore` package directly.
`tests/fixtures/dashboard/` holds recorded public API responses (`/v1/meta`,
`/v1/elections`, `/v1/elections/{year}` for 1824, 1860, 1868, 1872, 1896, 2016 and 2024,
`/v1/states/GA`, `/v1/elections/{year}/per-capita` for those years and 1848 and 1864, and
`/v1/states/{GA,TX}/per-capita`, and the candidate index `/v1/candidates` with
`/v1/candidates/andrew-jackson`), all
from one snapshot, which `test_every_recorded_response_is_one_snapshot` checks: test input
only, on the `ec_state_roster_by_year.json` precedent in the root [`CLAUDE.md`](../CLAUDE.md), and a guard asserts that no
runtime module names one (`test_no_runtime_module_names_the_test_fixtures`). Their path → file
map is `tests/dashboard_fixtures.py`, stdlib-only so the e2e server can import it.

**Browser tests (#321, D082).** `tests/e2e/` drives the app in Chromium through Playwright,
at a 390 × 844 viewport: the home page, and the elections index's filter-to-URL chain (one
callback per change, no loop), back and forward, a pasted filtered URL, the column-name list
and the year slider's labels keeping a gap; and the one-election view's later link and back (#324). They carry the `e2e` marker, which the default
run deselects. Run them with `uv run playwright install chromium` once, then
`uv run pytest -m e2e`. `tests/e2e/conftest.py` starts `tests/e2e/serve.py` on a free
loopback port, from `dashboard/`, waits for its ready line naming that port, and stops it at
session end. The server imports the app,
replaces `api.CLIENT` with a client over the recorded responses (the seam
`test_dashboard_app.py` uses; an unrecorded path is `ApiUnavailable`), and checks that warmup
filled the cache before it listens, since warmup answers 200 either way; its start-up checks
are explicit, so `PYTHONOPTIMIZE` cannot strip them. No test
reaches the network: the server's audit hook refuses every non-loopback lookup and connection
and writes a sentinel the session fails on (`api.fetch`'s `except` would otherwise turn a
refusal into the degraded page), and every test fails on a browser request off the loopback
host or a console error. Each test also checks the page is 390 px wide.
`tests/e2e/dashboard_pages.py` holds the page ids, the field list and the expected data values
computed from the recorded responses; the tests read shared labels and constants from
`explore` directly. A page a story changes keeps its e2e test current there, and a new page's `on_miss` paths need recorded responses, or its
browser test sees only the degraded state. CI runs the suite in `e2e.yml` on changes under
`dashboard/` and the other paths D082 lists; it is advisory. pytest-playwright deletes
`./test-results/` (traces, kept by `--tracing retain-on-failure`) at the start of every pytest
session, the default unit run included, so copy a local trace out before running pytest
again; CI uploads them in the same job.

## Deployment

**The dashboard deploys separately (E9-S2, #277 / D071).** [`.github/workflows/deploy-dashboard.yml`](../.github/workflows/deploy-dashboard.yml) is `workflow_dispatch`-only, waits on the same `production` environment gate as the API deploy, and authenticates by keyless WIF into `uspv-explore` through a pool in that project, so nothing about the API's deploy identity can reach it. It exports `dashboard/requirements.txt` from `uv.lock` (the `dashboard` group only, `--no-emit-project`, so the deployed runtime has no `usvote` to import), deploys a new version **without promoting it**, probes it on its own version host, moves traffic, probes `explore.`, and only then deletes every other version — `min_instances`/`max_instances` are per-version settings, so a leftover version keeps its own pinned instance running. A failure before that cleanup moves traffic back to the previous version automatically. Runbook: [`docs/deploy-dashboard.md`](../docs/deploy-dashboard.md) (the project, budget and runtime service account, WIF, the domain, rollback, monitoring, and the cold-start and load measurements). The domain is a **DNS-only CNAME** with App Engine's managed certificate — unlike the API, it is not proxied through Cloudflare (D071(c)): the zone holds only the Search Console TXT record that verifies the apex and a grey-cloud CNAME from `explore.` to `ghs.googlehosted.com`, and the zone's "Always use HTTPS" setting the API sits under is left untouched (runbook §8). So there is no Worker, edge cache, rate limit or origin secret in front of the dashboard, and the **residual exposure** is egress: abuse could run it up before the budget's alerts, which lag by hours, fire the kill-switch — one of D071's flip conditions (runbook §11). Cloudflare *is* on the dashboard's data path, since every read goes to `api.` through the API's Worker and edge cache; `explore/api.py` depends on that in one place, stripping the `W/` prefix Cloudflare adds to the strong `ETag` when it compresses (`etag_version`). The budget kill-switch in `deploy/killswitch/` gained an App Engine target in #283 (`KILLSWITCH_TARGET=app_engine` sets the app `USER_DISABLED`; never `max_instances: 0`, which App Engine reads as no cap), and the daily `api-canary.yml` probes `explore.` beside the API.

### `dashboard/` — the public dashboard (E9)

A Plotly Dash app (D071) that is **not part of the `usvote` package** and imports nothing from it (D070(b)). `dashboard/` is the App Engine **deploy root**: `app.yaml` (one pinned F1 instance with warmup, one gunicorn worker so one process and one cache, the least-privilege runtime service account, no `env_variables`) and a `.gcloudignore` **allow-list** that uploads only `app.yaml`, the exported `requirements.txt` and the app package, so nothing new under `dashboard/` ships by accident. The package is `dashboard/explore/`:

- `config.py` — the API base and the canonical host, as **constants**. Neither is configurable, because a base URL supplied by configuration is a second data input that no source-text guard can see.
- `api.py` — the dashboard's only way to read data. `fetch` is the **one outbound chokepoint**: `/v1/` paths and the one literal `HEALTH_PATH` (`/health`, D076), built on the fixed base, scheme and host checked before opening, no redirects followed and no proxy variables honored. Behind it sits an in-process cache keyed on `snapshot_version` (each response's `ETag` is the snapshot's content hash), refilled by one daemon refresher thread that prefetches every registered path and swaps the cache whole; fills pass a token bucket kept under the API's per-IP rate limit (D071(d)). D072 sets the MVP prefetch extent to `/v1/meta` and `/v1/elections`, with a year filled on a miss; the landing page registers `/v1/meta`, and both elections pages, both state pages and the candidate history `/v1/elections` (#306, #307, #279, #331; the refresher fills a path once however many pages register it), and `TestCache.test_the_process_client_prefetches_what_pages_register` (`test_dashboard_app.py`) pins that set. **Pages read only through `CLIENT.view()`** (#305), which pins one snapshot for the whole render: a miss whose response names another version raises `ApiUnavailable` (the page shows its degraded state) rather than mixing versions, and wakes the refresher; so a page also stays degraded while the API edge serves a year path and `/v1/meta` at different versions, a window the deploy's edge purge closes (D072; #314 asks whether a stale entry can land after it). A render has one deadline, `MAX_REQUEST_WAIT_S`, shared by its wait for the first snapshot, its fill tokens and its fetches (each capped at `VISITOR_FETCH_TIMEOUT_S`, against the refresher's `FETCH_TIMEOUT_S`); a fill that would leave its fetch less than `MIN_USEFUL_FETCH_S` is refused before it takes a token. After a successful refresh a visitor's wake-up is never dropped but is answered at most once per `MIN_RECHECK_INTERVAL_S`; after a failed one the refresher backs off unwakeably. **The keep-warm ping** (#346, D076): after every refresh attempt, succeeded or failed, the refresher GETs `/health` if one `REFRESH_TTL_S` has passed since the last ping *started* (stamped at the start, success or failure), so the Cloud Run origin does not scale to zero while the dashboard runs. It takes no bucket token, logs `api ping /health <elapsed>s` (a warning when the API is unavailable; any other error is a bug, logged at error level with its traceback) and never `api fetch`, discards its body (`/health` names the origin's snapshot version, never the cache's), and never counts as a failed cycle. Once a ping has been attempted, the wait after a successful cycle also ends when the next ping is due, so the worst gap between pings is, best effort, one TTL plus one unwakeable 30 s wait plus one full refresh (about 6 min); that ping-due cycle refreshes too and is not held to `MIN_RECHECK_INTERVAL_S`. Warmup, `refresh()` and visitors never ping, and a refresher that starts with a snapshot already serving waits one TTL first, so the guard's success run never pings. No page can read `/health`: `_fill` and `_visitor_fill` refuse it (`_refuse_health`), `test_only_api_names_the_keep_warm_path` (`test_dashboard_guards.py`) keeps the literal out of every other runtime module, and `test_only_the_refresher_cycle_calls_the_ping` makes `Client._cycle` the one place any runtime module refers to `_ping` (who calls `_cycle` is not checked; `TestKeepWarm.test_warmup_never_pings` and `test_a_visitors_miss_never_pings` cover today's request paths); `TestKeepWarm` drives the real `_run` on a fake clock. The refresher starts lazily, never at import, so importing the module makes no network call. **Coverage variables** (#279, D074): `COVERAGE_VARS` (`year_max`) is the closed set of names an `on_miss` template or a `validate` source may use besides a page's path variables; `coverage_vars` reads them from a `/v1/elections` body, accepting `year_max` only as the latest year that body serves, and never from a request. `ROSTER_PATH`, `/v1/elections/{year_max}`, is the state roster. `CANDIDATES_PATH`, `/v1/candidates` (#330), is the candidate index: the candidate history's `validate` source, a literal declared in `on_miss` (D074(ii)) and filled on a miss, so D072's prefetch extent is unchanged.
- `app.py` — the Dash app and its WSGI entry point (`explore.app:server`). It 301s the `appspot.com` host to `explore.`; names each page's URL from the page Dash's router matches (D073, #312): `resolve` asks `dash._pages._path_to_page`, and a matched path gets a canonical link built from the page's path template and its variables (no query string) and an `og:url` adding the query as the page's `query=` parser normalizes it, while a path no page matches, one a page's `validate=` rejects from the snapshot already in memory, one whose percent-escapes change it when decoded (`raw_path`: gunicorn's `RAW_URI` as sent, normalized to one leading slash as Werkzeug normalizes `request.path`, against the decoded path — Dash's router matches the browser's still-encoded `location.pathname`, so only a path with no effective escape is matched the same way on both sides; the runbook's §9 checks after a deploy that App Engine's front end passes the raw target through), or Dash's custom-404 module `not_found_404`, answers **404** with `noindex` and neither tag (a source not cached yet counts as matched, so the index never waits on the API). `og:url`'s query pairs are de-duplicated, so a repeated filter names the same URL as a single one. It rebuilds Dash's page card tags itself (`include_pages_meta=False`) without Dash's `twitter:url`, which is the raw request URL, and the index resolves once per request, so its status and tags always agree. **The path's value wins** (#326, D081): Dash's router merges the query string over a page's path variables, so its `before_request` hook rewrites the Pages routing request first, dropping from the `search` input every key named after a path variable of the page the `pathname` input matches (`strip_path_variables`, which reads keys as the router's `parse_qs` does), so a render always matches its canonical link. The hook is gated on the dispatch endpoint and the router's `output`, reads the two inputs by position, and writes into the body Werkzeug caches, which is the object Dash's `get_json()` returns. The Dash privates and internals it relies on are pinned in `TestDashPrivates`, and `TestPathVariableWins` drives the real routing request on every registered templated page, with a control that fails each one with the hook off. It fills the cache synchronously on `/_ah/warmup`, and sets `suppress_callback_exceptions=True` so the index HTML carries no data and never waits on the API — which is what keeps a link preview's time to first byte short (D071(g)).
- `pages/` — Dash Pages. Shareable views are **paths**, so each one server-renders its own Open Graph card (D071(a)); the query string carries filters within a view. Each page declares in `dash.register_page` every API path it reads: `prefetch=(...)` for paths the refresher warms on every new snapshot version, `on_miss=(...)` for paths filled on a miss (templates of the page's path variables, e.g. `/v1/elections/{year}` for `/election/<year>`, or of the coverage variables, e.g. `/v1/elections/{year_max}`, D074), and `success=` the id of an element it renders only from a successful read. `TestRegistryCoverage` renders every page (templated ones at a concrete value) from recorded responses and fails an undeclared read or a missing marker, and `test_pages_read_only_through_a_render_scoped_view` (its rule is `client_misuses`, both in `tests/unit/test_dashboard_app.py`) fails a page that reaches `explore.api` other than through `CLIENT.view` (a module imported under another name, such as `from explore import api as x`, is not tracked). `TestRegistryCoverage` runs layouts only (the lint scans the whole page source, callbacks included): a page's callbacks that read the cache must be covered by the page's own tests. Two more keys, both optional (#312): a templated page registers `validate=(source, judge)` (`api.Validate`) — a source path that is a literal it lists in `prefetch`, or (D074, #279) one it declares in `on_miss`, a literal or a template over the coverage variables, and never one built from a path variable; and a pure, total `judge(path_vars, body) -> bool` (a judge that raises anyway is logged and refuses, at the index and at render, rather than answering 500) — and a page that reads filters registers `query=` its parser. **A templated page formats a path variable into an API path only after `api.accepted(view.get, VALIDATE, {...})` accepts the keyword arguments its layout received**, because the routing request never passes through the index, a greedy path variable takes any segment (`/election/1824/x`), and the path itself can name a hostile value (`/election/..`); app.py's hook keeps a query key from overriding the variable (D081), and this check stays behind it in case a Dash upgrade disables it (`test_without_the_hook_every_page_refuses_a_hostile_query_value` renders `QUERY_RENDERS` with the hook off); a refused value renders the page's not-found state and never fills (with the source cold, at most one fill, of the source itself). Without it, `fetch` refuses a malformed path with `ValueError`, which the `except` in `pages/home.py`'s layout does not catch, and a junk year takes a fill token. `TestValidateBeforeFill` renders every registered templated page through the routing request at hostile values and fails one that fetches, takes a token, errors or renders its success marker; `TestRegistryContracts` fails a `validate` source the page neither prefetches nor declares in `on_miss`, or builds from a path variable, an `on_miss` placeholder that is neither a path nor a coverage variable, and a `query=` parser that is not total over hostile input, returns anything but `str` pairs, is not idempotent through re-encoding, or emits a key named after a path variable (app.py drops such a key before the render, while `og:url` would still name it). A parser runs at index time, so it reads no API; a callable `title` or `description` is called by Dash with **unvalidated** path variables, at index time too, so it must be total and read no API.
- `components.py`, `labels.py` (#306), `query.py` (#307) and `export.py` (#309) — the pieces every table shares: pure functions of what a page already read (a response's provenance, a field name, a cell value), importing nothing from `explore` but each other, by name and without a cycle (`TestSharedPieces.test_the_shared_modules_read_no_api` and `test_the_shared_modules_import_each_other_without_a_cycle` in `test_dashboard_elections.py` check it). **Every table goes through `components.table`** (#309, D075; `TestEveryTable` in `test_dashboard_export.py` records its calls while rendering every registered page and fails a table it did not build, or one without its link), which builds its body and its CSV download from one row list: the file sits in the link's `data:` URL, built in the render, so a download makes no request and has no route or callback, and with no rows there is no table and no link. The link is the scroll box's next sibling. `export.py` writes the file: a byte-order mark, a preamble of `#,<sentence>` rows (each source the table carries with its license, from the response's own `meta.provenance`, labeled by what it supplies; the snapshot version; the Electoral College years, and the popular-vote years where the table carries them; the view's URL with the filters the render applied; the table's notes, passed to `components.table` and shown under it too; what an empty cell means), a blank row, the header of raw public field names (the displayed fields, then the count reason where a table shows it only in a cell, then the party note T2–T5 show under the table, then the party's per-row source, `nominating_party_source`, which no table shows and which keys nothing: per-row provenance, a column category #389 added to D075's, so a reader can tell which rows the curated source supplies; then the keys `state_usps` / `candidate_slug` / `year` where a table shows them not at all) and the rows. A null is an empty cell, text gets a `'` before a formula character at its start or after leading whitespace, a field holding a `#` is quoted (so `pandas.read_csv(f, comment="#", encoding="utf-8-sig")` skips only the preamble), and the sources come from the columns through four disjoint field sets (`EC_FIELDS`, `POPULAR_VOTE_FIELDS`, `CENSUS_FIELDS`, `NOMINATING_PARTY_FIELDS`, the last crediting `USGOV_SOURCE`, #389; `test_the_field_sets_are_disjoint_and_cover_every_column` fails a rendered table exporting a field in none of them). It builds the text in memory and writes RFC 4180 rows itself, because the guard bans `csv` and `io` from runtime modules. `components` holds the **provenance footer**, built from a response's own `provenance` (`/v1/meta`'s, or the `meta.provenance` every other response carries) and shown on every view that rendered data, listing all four sources (`components.SOURCES`), and the degraded state, `UNAVAILABLE_MESSAGE`, whose wording `scripts/probe_dashboard.sh` greps, so it changes only together with that script. `labels` holds **the one label table**, `LABELS`, keyed by public `/v1` field name, never a snapshot column (`TestLabels.test_every_label_keys_a_public_api_field_never_a_snapshot_column` checks each key against `usvote.api.models`' field names and their `validation_alias`es); a later table adds rows to it rather than labeling inline. The table is flat, so a key means one thing everywhere, and a field name the API uses with two meanings needs a qualified key for the second: `candidate_count` already is one (a `/v1/elections` row's per-year count, against `/v1/meta`'s distinct candidates across the snapshot), and `coverage` is another: the plain key is a per-capita row's (#280), so the provenance block's year windows would need a qualified one. Each header carries its raw field name as a tooltip, and `labels.glossary` builds the column-name list that repeats them under the table for touch screens. `has_popular_vote: false` reads `labels.NOT_IN_DATASET`, never a bare negative. **Reader-facing wording lives in code, not here:** `labels.py` holds the labels, the closed-value tables and the null and help-text constants, with a few page-level sentences in `components`, `export` and the pages; the project glossary, [`docs/glossary.md`](../docs/glossary.md), records what each term means and the wording rules every label follows (no underscore or raw field name in a label, cell or note; "counted" only for vote counts; #352). The `ba` agent maintains the project glossary and drafts new wording as a label spec against it (root `CLAUDE.md`, *Who writes wording*). This file names constants rather than quoting their text. **No cell `labels` words shows a raw value** (#355): a null or blank names no cause (`labels.NOT_IN_DATASET`, or the cause its row gives), any other value a cell has no wording for (an unknown code, a wrong type, a non-finite number) reads `labels.UNRECOGNIZED`, and `labels.cell` builds every label-produced `Td` (and the panel's `Dd`) so such a cell carries `labels.UNRECOGNIZED_NOTE` as its help text. Candidate and state names are shown as served, an open vocabulary the API types as text (#367 would route them too). `TestNoRawValues` (`test_dashboard_export.py`) renders each table page from recorded responses and from doctored bodies (`DOCTORED`: a sentinel in every closed-vocabulary and yes-or-no field each page shows, one numeric field per table, a non-text name, and the party, a closed vocabulary since #389, with a text row note), and fails a page whose rendered text (children, dropdown labels and placeholders; not tooltips) carries an underscore or a served code, whose unrecognized cells lack the note, or whose count of them per table differs from `UNRECOGNIZED_CELLS`. The party is the nominating party (#389, D077), one value per candidate per election: each code shows its display form from the closed table `labels.NOMINATING_PARTY` through `labels.nominating_party`, so a code outside it reads `labels.UNRECOGNIZED`; the download keeps the code. The popular-vote source's `party` is on no page and in no download. `labels` also holds the cells a null or a closed value can reach (#307): a label for each closed value of `pv_status` and `electoral_count_status` (tested against `usvote.pv.status` and `usvote.count_status`), the popular-vote null table (`popular_votes`, which takes the window from `coverage` and reads a year before, after or inside it differently), the party cell (`nominating_party_cell`, used by T2–T5: `labels.NO_NOMINATION` with its note, a null with `labels.PARTY_NULL_NOTE`, and a row's note as help text) and the Party notes list each of those tables shows under it (`party_notes`, once per candidate-year shown), and the count-status cell with the Archives' reason verbatim. `query` holds URL-state syntax, because a page module cannot import another: the single-value rule, `encode_search` (the one normal form `og:url` and every filter callback write), the year, USPS and slug patterns, and the shared year range (#279): its keys and parse, `checked_year` (the one check of a year read from a body, which `api.coverage_vars`, `year_span`, the one-election view, the state history and the picker use; the elections index's rows are not yet checked, #334), a served span, and the bounds a render applies. `components` also holds the year-range slider every year-filtered table uses, the candidate history's single-choice year control (`year_buttons`, #331), and the two linked name cells: `state_cell` (a state's name, linked to `/state/<usps>` only for a USPS code; T2, T5 and T6) and `candidate_cell` (a candidate's name, linked to `/candidate/<slug>` only for a `str` slug `query.is_slug` accepts and a name with text in it; T2, T3 and T4), so `components` imports `query`.
- `pages/election.py` — the one-election view, the election panel (#308), T2 and T3 (#307) and T6 (#280), at `/election/<year>`. The panel, T2 and T3 come from one `/v1/elections/{year}` response (its `election` block, `data` and `summary`) and T6, every state's persons per electoral vote, from `/v1/elections/{year}/per-capita`; both are filled on a miss in the same render, so a failed per-capita read degrades the whole page and the success marker covers the panel and all three tables. **The earlier and later links** (#324) come first, in a `Nav` landmark: to the nearest year before and after that `/v1/elections` serves (`neighbours`, read from the index rows the page already read, never `year ± 4`), unfiltered, with no link on a side that has no year and no landmark with neither; they render only on success, as the lede's filter sentence (`FILTER_SENTENCE`) does, so the not-found and degraded states show neither. A link costs only the target year's own fills. **The panel** (`election-panel`, first after those links and never filtered) lists who led under each method (the `ec_winner` row's label, in the list and its field-name list alike, chosen by `labels.ec_winner_label` from `ec_determinative`, and a flip naming the Electoral College's winner or leader by the same test, #355), whether the popular-vote or the hybrid winner differs from the Electoral College's, the three margins (in percentage points, as the API serves them), whether anyone won a majority of electors appointed, and `pv_coverage`, each label tooltipped with its field name, with the hybrid's one line of help text (`labels.HYBRID_NOTE`, under T3 too), the margins' (`labels.MARGIN_NOTE`) and a field-name list (the same `labels.glossary` list, titled for a list that is no table). Its cells come from `labels` (`winner`, `flip`, `margin`, `ec_majority`, `share_cell`): a null popular-vote or hybrid field outside the window (`labels.in_pv_window`, from `coverage`) reads `labels.NOT_APPLICABLE`, never a bare negative; inside it, and for the Electoral College fields at any year, a null names no cause; a value is shown whatever the year, as T2's popular votes are. `render` checks the window once with `query.year_span` before any cell reads it, whatever the `election` block holds. The `election` key is required; the API serves `election: null` on a build gap while the rows stay correct, so a null renders the panel's own sentence (`election-panel-unavailable`) and the tables, while any other shape, a block naming another year or a missing panel field degrades the page, as a malformed window does with or without a block.
