# CLAUDE.md — `src/usvote/`

Module-specific guidance for the `usvote` package. Claude Code loads this file on demand, once a file under this directory is read, including files in the `census/`, `pv/` and `api/` subpackages. The root file's module map and cross-cutting invariants still apply. How each rule below was found is recorded in [`.claude/specs/decisions.md`](../../.claude/specs/decisions.md); this file keeps the rules.

## Entry points

Every package `__main__` dispatches subcommands (#84b, D027). The bare spellings differ by package, but each is a *named default subcommand*:
- `python -m usvote` — bare is **EC** (`--replace` works bare). Subcommands: `ec` (the default) and `all` (the whole-warehouse build via `usvote/warehouse.py`: EC + MIT + optional UCSB + optional census + views).
- `python -m usvote.ucsb` — bare is **snapshot** (the D023 network refresh into `USVOTE_UCSB_HTML_DIR`), kept for backward compatibility; `load` runs `run_ucsb_pipeline`.
- `python -m usvote.mit` — a single `load` subcommand (the default). MIT reads a local CSV, so there is deliberately no `snapshot`.
- `python -m usvote.census` — bare is **load**; `snapshot` (into `USVOTE_CENSUS_CORPUS_DIR`) is its only network command. Census takes MIT's default, leaving UCSB the documented exception.

`usvote all` is the only cross-source orchestrator, so there is no top-level `mit`/`ucsb` subcommand (one spelling per action). Both PV `load`s reconcile against `dwh`, so load the EC spine first.

## `warehouse.py` — the composition root

`usvote/warehouse.py` is a **composition root** (E6-S3, #84b). `run_warehouse` sequences EC → MIT → (optional) UCSB → (optional) census → view rebuild → the #167 overlap gates, and it is the one top-level module that imports from every source. A composition root sits **above** EC and PV, like `__main__`, so this does not break D015 (D027). The exemption holds only one way: **nothing under `usvote/{mit,ucsb,pv,census}/` may import `usvote.warehouse`** (`test_no_pv_source_imports_the_warehouse_composition_root`).

`rebuild_views` is the one place view ordering is expressed: the chain `build_pv_union → create_ec_pv_views → create_hybrid_views`, then `create_per_capita_view` as a **non-chain** step that **skips rather than raises** when `dwh.election_population` is absent, so a public EC + MIT clone still builds (D064(e)). It probes for the table rather than for this build's corpus, so an `all` build with no census corpus still refreshes the view over a previous census load's facts. Because `run_ec_pipeline(replace=True)` runs `DROP SCHEMA dwh CASCADE`, the views are **always rebuilt** as the final step. `python -m usvote.census load` creates the per-capita view itself, from `usvote/census/__main__.py`: each entry point's composition layer owns view creation, and the shared pipelines stay view-free (D064(c-bis)).

The build is **per-source atomic, not globally atomic** (each pipeline owns its transaction, #84a). After a mid-build failure, recover with `run_warehouse(..., replace=True)`; a bare re-run hits a unique-violation on the first already-loaded source. That recovery does **not** help a D017 layer-3 breach (#167): the gates run last, so `replace=True` rebuilds the same facts and re-hits it. The escape is `--no-validate-overlap` (`validate_overlap=False`), because gate 1's per-year floor is the threshold D051 expects to retune first.

## Dependency-free EC-domain modules

`usvote/years.py` holds the election-year domain constants (`ec_ingest_years`, `UNSUPPORTED_EC_YEARS`) and is deliberately dependency-free, so a pure transform can derive its year scope from the EC spine without importing the orchestrator (and its DB/network stack). `usvote/pipeline.py` re-exports those names.

`usvote/count_status.py` (#143/#144; D043 §3, D044, D046) is stdlib-only for the same reason. The `dwh.votes` count-status enum (`counted` / `not_counted` / `disputed`, with `build_count_status_check`) has **two callers that must not depend on each other**: `transform.py` assigns the values and `load.py` builds the `CHECK` from them, so a home in either would drag pandas into the DDL builder or psycopg2 into the transform chain. (The value-tuple `CHECK` pattern comes from `usvote/pv/status.py`, which is **not** stdlib-only.) `COUNTED_VOTES_COLUMN` (+ `build_counted_votes_check`) lives here too, because the enum defines it: a row's counted votes are its cast votes when `counted`, else 0.

`usvote/apportionment.py` (#182 / D060) is top-level rather than under `usvote/census/` because it is keyed on the **election** year and imports only `usvote.years`. Which apportionment was in force is an election-domain fact, and a non-census consumer would otherwise import up from a source subpackage. It holds `governing_census_year` and `GOVERNING_CENSUS_BY_ELECTION`, and it is **a lookup, never a formula**. A census taken in year *C* governs elections from *C+2*, except that no apportionment act passed after the **1920** census (`NO_APPORTIONMENT_CENSUSES`), so **1924 and 1928 are governed by 1910**. Nearest-decade rounding is wrong (it maps 2020→2020 where the answer is 2010), and a bare decade lag is wrong for 1924/1928. The offline oracle is a **hand-written literal** of every election year; the allotment cross-check is an integration test, because the counts exist only in `dwh.votes`. The dependency-free property is enforced by an import scan and by a subprocess import with pandas/psycopg2/requests/geopandas blocked, plus a non-vacuity twin. `governing_census_year` is the apportionment in force, not the latest enumeration, so the 1924/1928 per-capita denominator is 14-year-old population, by choice (D060(c)).

## `spine.py` and `join.py`

`usvote/spine.py` holds **EC-spine readers** (`read_ec_participation`, `read_ec_getters`) that a PV source uses to pull EC facts out of `dwh.votes`/`dwh.candidate` across a DI seam. It is top-level, not under `usvote/pv/`, because it embeds EC star-schema knowledge.

`usvote/join.py` is the **EC<->PV join seam** (E6-S2, #69 / D026). It joins a **resolved** PV series onto the EC spine: `pv_preferred` for analysis, `pv_redistributable` for the API, never the raw `dwh.pv_votes` union, which fans out 2× over the 1976–2024 overlap (D017). It is an **EC-left join** at `(year, state, candidate)` grain, exposed as `ec_pv_preferred` / `ec_pv_redistributable`. EC-left is correct because the EC `votes` fact is **dense**: the Archives' `-` parses as `0`, so a loser is an explicit 0-EV row, not a missing one (`transform.assert_rectangular_state_grain`). Losers survive the join with their PV attached, and a getter with no PV keeps NULL PV (an honest D005 gap). The one EC-left footgun, a PV row matching no EC row being dropped silently, is caught by the fact-level anti-join `assert_db_pv_matches_ec`, a view-creation precondition.

`national_electoral_votes` and `national_counted_electoral_votes` are `SUM(...) OVER (PARTITION BY year, candidate_id)` windows, exact on the dense fact. The counted measures and `count_status`/`count_status_reason` are surfaced publicly (D047/D048); the view excludes `is_total` rows, the one place D044 says count status must not be read. **`EC_PV_COLUMNS` is append-only**: `CREATE OR REPLACE VIEW` can only add trailing columns, so a mid-list insert breaks `rebuild_views` against an existing warehouse. `snapshot_schema.DATA_COLUMNS` is an **independent explicit projection**, not derived from this tuple, so a new column here reaches neither the snapshot nor its content hash until it is listed there too. A test asserts `DATA_COLUMNS ⊆ EC_PV_COLUMNS ∪ derived`; the reverse assert is forbidden (D047 §3).

## `hybrid.py` — the three-method computation core

`usvote/hybrid.py` (E7-S2, #121 / D037/D038/D041) rolls a resolved join view up to per-`(year, candidate)` national outcomes and scores three methods: the EC share, the PV share, and the **hybrid**, `(ec_share_hybrid + pv_share) / 2`, highest wins (D037). `build_hybrid_frame` is per candidate; `build_hybrid_summary` is per election (three winners, `ec_determinative`, `pv_coverage`, two flips, three margins). Both column tuples, `HYBRID_CANDIDATE_COLUMNS` and `HYBRID_SUMMARY_COLUMNS`, are **append-only** view contracts; with `hybrid_summary_*` built on `hybrid_*`, a breaking change needs a `DROP ... CASCADE` migration. Their order is pinned by **hand-written literal** asserts (e.g. `TestShape.test_the_summary_column_order_is_pinned_to_a_literal`). An assert comparing the frame with the constant would be circular, because the frame is built from it.

- `pv_flip` / `hybrid_flip` compare each method's winner with the EC baseline, `argmax(ec_share_full)`: rank 1, **never** `took_office`, which differs in a contingent election. They are **nullable**: a method with no winner yields NULL, never `false` and never `true`. `_winner` returns a Python `None`, so a bare `!=` would report a flip on every pre-1976 year when UCSB is absent.
- `ec_margin` / `pv_margin` / `hybrid_margin` are top-2 **percentage-point** gaps over **each method's own non-NULL scores**, because faithless electors give some years candidates with electoral votes and no popular vote. With fewer than two scored candidates a margin is NULL, never `top1 - 0`. `ec_margin` reads `ec_share_full`, keeping it coherent with `ec_winner` and `ec_determinative`; `hybrid_margin` tracks `hybrid_score`.

**The EC share is split in two, as a safety property** (D037/A). `ec_share_full = national_counted_electoral_votes / ec_denominator` is policy-invariant and the **only** input to `ec_determinative`; the policy-selected `ec_share_hybrid` feeds only `hybrid_score`. So no coverage policy can manufacture a constitutional majority. The naive restriction, trimming 1824's denominator to the popular-vote states but not the numerator, would put Jackson at 99/190 = 0.52, when his real share is 99/261 = 0.379 and the House decided. `ec_denominator` is the **appointed** allotment (each state's `total_electoral_votes` counted once, not summed over joined rows), the 12th Amendment's "whole number of Electors appointed", while the numerators are votes **counted** (D046). EC shares therefore sum to **≤ 1.0**: 2000 is Bush 271 of 538 appointed against a 270 threshold (D041), and 1872 is Grant 286 of 366. `president_electoral_rank` is on the counted basis too, and must switch together with the shares, because `assert_ec_winner_matches_rank` compares `argmax(ec_share_full)` with rank 1. `ec_determinative` is `true` only on a **strict** `> 0.5`; `false` means *no EC majority*, an expected state and the hybrid's motivating case, never a null-because-broken.

**`dwh.pv_state_status` is a first-class input.** `EC_PV_COLUMNS` has no `pv_status`, and `pv_coverage` (Σ EV over `popular_vote` states ÷ `ec_denominator`, EV-weighted, D024 §8) **cannot be inferred from a NULL `candidate_votes`**: that would conflate a state that held no popular vote with one the source does not cover. The denominator policy is **(b)** (D038), applied in `apply_coverage_policy`; policy (c) is reachable from Python only. [`docs/pv-coverage.md`](../../docs/pv-coverage.md) explains the column. On the `hybrid_redistributable` **view** every pre-1976 `pv_coverage` reads NULL, while the public snapshot carries the real figure (D053): the one deliberate divergence.

The SQL lives in four views (#124 / D050): `hybrid_preferred`/`hybrid_redistributable` per candidate and `hybrid_summary_preferred`/`hybrid_summary_redistributable` per election, created by `create_hybrid_views` after `create_ec_pv_views`. The SQL implements **policy (b) only**. A view cannot `raise`, so the tie check is the separate `assert_no_winner_tie`, a view-creation precondition. The pandas builders are the **tested oracle**, but `create_hybrid_views` runs its guards on the pandas side, so SQL/oracle drift is caught only by `tests/integration/test_hybrid_views.py::test_the_live_views_match_the_pandas_oracle`, which is deliberately not corpus-gated. `party` is **resolved by `min`**, because MIT (`REPUBLICAN`) and UCSB (`Republican`) spell parties differently and `pv_preferred` resolves per key. `snapshot.build_national_rollup` **calls** `roll_up_national`, so national aggregation has one derivation (D037/F, D029).

## `snapshot.py` — the API serving-store build

`usvote/snapshot.py` (E8-S1, #94 / D028) materializes `ec_pv_redistributable` into a **read-only SQLite snapshot** (`python -m usvote.snapshot` → `USVOTE_API_SNAPSHOT_PATH`) that `usvote/api/` serves with **no live DB**. It replaces `candidate_id` with a deterministic public `candidate_slug` (`usvote/slug.py`, D006), is versioned by a content hash rather than a timestamp, and is redistributable-only at the source (D030). Its tables (`ec_pv`, `national_rollup`, `hybrid_summary`, `per_capita`, `snapshot_meta`) are documented in [`docs/api-snapshot.md`](../../docs/api-snapshot.md). `usvote/snapshot_schema.py` holds only the contract (names, `SnapshotMeta`, the schema version) and is **stdlib-only**, so both sides of the D028 boundary can import it. A schema-version bump means a snapshot and the image serving it must cut over together (D034).

**The served window is the full EC span** (#139 / D048). `snapshot_meta` states two windows, served (`year_min`/`year_max`) and popular vote (`pv_year_min`/`pv_year_max`), so coverage is stated rather than inferred from nulls. Every fact row has a `NOT NULL` **`pv_status`**, so a null popular vote is never bare: 1860 South Carolina (`legislature_chosen`) and 1860 New York (`popular_vote`, no source) mean different things. That status is derived **in-process from `usvote/pv/absences.py` over the EC spine, never from `dwh.pv_state_status`**, whose pre-1976 rows are UCSB-derived (D022); `test_layering.py` proves it by importing `usvote.snapshot` with `usvote.ucsb` unimportable. The roster raises on a short warehouse, so **a scoped warehouse cannot build a snapshot**. `count_status` and both counted measures are surfaced, `national_rollup` carries the appointed denominator, and provenance is per source (`ec_source`/`ec_license` NARA / US-PD beside MIT / CC0). `count_status_reason`, the one free-text column, ships only because the build pins it to a closed vocabulary of Archives sentences.

**The three-method comparison ships publicly** (#102 / D053). `national_rollup` carries the five per-candidate hybrid fields, and `hybrid_summary` the per-election grain (winners with slugs, flips, margins, `ec_determinative`, `ec_denominator`), returned as an `election` key by `/v1/elections/{year}` and `/v1/elections/{year}/summary`. The snapshot **recomputes** the hybrid with `hybrid.build_hybrid_from_frames` over the join frame and the **curated** roster, rather than reading `hybrid_redistributable`: no extra DB read, and `pv_coverage` resolves to the in-repo catalog. Pre-1976 `pv_coverage` is the one intended divergence from the view; under policy (b) it feeds no score, so everything else matches, which `tests/integration/test_snapshot_build.py` pins. `build_hybrid_from_frames` is an extraction of `build_hybrid_from_db`, so this path keeps the same guards, above all `assert_no_winner_tie`. `snapshot_schema.HYBRID_SUMMARY_COLUMNS` is an **independent explicit projection** of the hybrid tuple, not an alias (D047 §3).

**The per-capita series ships too** (#245 / D069): the `per_capita` table, keyed `(year, state)`, carries `dwh.election_per_capita` and is served at `/v1/elections/{year}/per-capita` and `/v1/states/{usps}/per-capita`.
- **Census is a required snapshot input**: `read_per_capita` fails loud without the view, so an EC + MIT clone builds a warehouse but not a snapshot. UCSB is **never** required, because its absence is a licensing firewall (D022/D030), not a convenience.
- **The view is read by SQL name, not by import**, since `snapshot.py` may not import `usvote.census`. The view name and columns are local literals, the three closed vocabularies are copies in `snapshot_schema.py`, and `TestPerCapitaContract` pins each copy to its census original.
- **The content hash covers `ec_pv` and `per_capita`** (every column but the float ratio) and excludes the derived tables, so a census reload moves `snapshot_version` and triggers the D034 cutover. The build refuses a ratio other than `population / total_electoral_votes`, and checks `per_capita` against `ec_pv` in both key directions and on every row's `total_electoral_votes`.
- Provenance has three sources: `census_source`/`census_license` (USCB / US-PD) join the NARA and MIT pairs.

## The `votes` fact (`dwh.votes`)

Three measures form a ladder, **appointed ≥ cast ≥ counted**: `total_electoral_votes` (the appointed allotment), `president_electoral_votes` (votes **cast**) and `president_electoral_votes_counted` (#144 / D046). `ELECTORAL_VOTE_SHORTFALLS` records votes **never cast** and opens the first gap; `count_status` opens the second. The two are disjoint, since a cast-then-rejected row still sums to its allotment.

- **`count_status` + `count_status_reason`** (D043 §3 / D044) say whether cast votes were **counted** by Congress, with the source's own sentence as the reason. The grain is `(year, state, candidate)`, because 1872 Georgia counts 8 of its 11 votes (D043 §4). Aggregate `is_total` rows are never flagged.
- **The counted rule is strict**: `disputed` is excluded alongside `not_counted`, which is what makes **both** of the Archives' printed 1868 totals reproducible (294 cast, 285 counted). State rows take the row rule; an `is_total` row takes the sum over its year's state rows, because the row rule would hand back the cast value.
- **`president_electoral_rank` and `took_office` come from the counted measure**, since Congress's count settles who won. `took_office` is the rank-1 candidate except in contingent elections such as 1824, where the House chose someone else (`CONTINGENT_OFFICE_HOLDERS`, [`docs/corrections.md`](../../docs/corrections.md)).
